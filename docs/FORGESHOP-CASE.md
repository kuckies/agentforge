# ForgeShop: исправление сложных диалогов

10 ноября 2026. Учебный магазин с вымышленными заказами; локальная Qwen2.5-7B-Instruct Q4_K_M. Бот использует модель для выбора категории и выдаёт ответы из фиксированной базы. Он не выполняет платежи и не изменяет заказы.

## Результат

| Проверка | До: support-v2 | После: support-v3 |
|---|---:|---:|
| Сложные диалоги | 8/12 | 12/12 |
| Шаги в этих диалогах | 26/32 | 32/32 |

Промпты, ожидаемые ответы, порядок и типы проверок в сравнении совпадают. Полное совпадение разобранного JSON проверяет категорию, текст ответа и данные заказа. До и после используется один локальный сервер модели, temperature=0, seed=42. Версия инструкции и логика памяти изменены вместе: результат относится к их совокупности.

До сравнения был разведочный прогон с общим ответом unknown на просьбу забыть номер. Затем критерий был уточнён: бот должен явно подтвердить забывание. Таблица использует отдельный повторный исходный прогон с этим окончательным критерием; сравниваемый набор после него не менялся.

## Найденные проблемы и исправления

1. После «Забудь номер заказа» бот подставлял прежний заказ в следующем запросе трека. Добавлена категория forget_order; она очищает сохранённый номер и ожидание номера, затем явно подтверждает действие.
2. «Трек-номер другой посылки» возвращал трек прошлого заказа. Теперь новый заказ, посылка или отправление без номера требуют уточнения. Явно указанный новый номер имеет приоритет.
3. Просьба создать вымышленный заказ выбирала проверку статуса. Классификатору уточнён ответ unknown. До исправления заказ также не создавался: база оставалась неизменной.
4. Просьба изменить статус после оплаты выбирала проверку заказа. Теперь это вопрос оплаты с передачей оператору. Оплата и изменение статуса по-прежнему не выполняются.

Первое изменение инструкции исправило память, но дало две ошибки классификации. Уточнение формулировок исправило их; окончательная версия повторно проверена на всех трёх наборах.

## Дополнительная проверка

- Сложные диалоги: два успешных прогона окончательной версии, каждый 12/12, 32/32 шага.
- Прежние отдельные обращения: 20/20.
- Прежние диалоги: 10/10, 26/26 шагов.
- Шесть дополнительных перефразировок, не использованных при исправлении инструкции: 6/6 категорий, включая «Не забудь проверить заказ» и просьбу удалить номер из памяти. После этой проверки инструкция не менялась.
- Автоматические тесты приложения: 51 успешно; проверены очистка памяти, несколько обозначений новой посылки и выбор нового набора в интерфейсе. pip check без ошибок.

## Повторение

Откройте Start-TestBot.cmd. В AgentForge выберите «Бот поддержки (учебный)» → «Сложные диалоги — 12» → «Запустить тесты». Набор хранится в scenarios-support-hard.json. Отчёт доступен для скачивания и в локальной «Истории».

На рабочем компьютере JSON-отчёты baseline и final сохранены в outputs/hard-dialogue-results вне репозитория; оба запуска также есть в SQLite. В Git пользовательская база не включена.

Это небольшой известный набор, на котором исправлялась система, и шесть дополнительных перефразировок. Результат не оценивает любые обращения, реальную интеграцию магазина, авторизацию или нагрузку. Сервер модели уже работал локально; платный API не использовался.
